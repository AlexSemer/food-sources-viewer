QUESTION:
How do we map USDA FoodData Central *Foundation Foods* nutrients onto our locked canonical Nutrient list, and what observation shape should hold one source-backed value without collapsing it into a single “true” Food.nutrients array?

WHY IT MATTERS TO THE PROJECT:
Intake targets and organ effects only work if every incoming number points at a stable Nutrient.id and keeps provenance. Foundation Foods is the cleanest analytical backbone. A small pilot proves the mapping and the observation table before any multi-source merge.

DONE WHEN:
1. FoodSource row specified for USDA Foundation (version / release month, URL, license CC0).
2. Crosswalk table: USDA nutrient id (`nutrient.csv` id / nutrient_nbr) → our Nutrient.id or UNMAPPED, with unit conversion notes.
3. Recommended observation fields (food source key, nutrient key, amount, unit as published, amount in canonical unit, basis e.g. per 100 g, derivation, sample notes if present).
4. Explicit list of USDA nutrients we will ignore in this pilot (archived, pH, specific gravity, etc.).
5. Recommendation: keep raw observations separate from locked Food; do not write brand or OFF rows.

IN SCOPE SOURCES:
- USDA FoodData Central Foundation Foods (latest published download page; do not pull other FDC types).
- Local `artifacts/nutrient.csv` (USDA nutrient dictionary already in repo).
- Local `artifacts/data/nutrients/canonical-nutrients.json`.
- Locked Nutrient entity + nutrient.schema.json (`usda_nutrient_id` field already exists).
- Locked FoodSource entity (FigJam).
- food.schema.json only as contrast (current schema embeds nutrients on Food; pilot may recommend not using that for source data).

OUT OF SCOPE:
- Downloading or aligning SR Legacy, FNDDS, Branded, Open Food Facts, FAO/INFOODS, FooDB, EuroFIR, CNF, CIQUAL.
- Creating Product / branded entity.
- Loading a production database or writing app code.
- Matching food *items* across sources (this pilot is nutrient-code + observation shape, not apple-to-apple identity).
- Averaging multiple Foundation samples into one Food row.
- Changing MASTER-UML or shipping schema CRs (recommendation only; CR comes after critic).

OUTPUT SHAPE:
- notes + two tables:
  - nutrient crosswalk
  - proposed FoodNutrientObservation field list
- recommendation (keep / drop / later)

CONSTRAINTS:
- Founder rule: confirm before each action. Researcher must not download bulk files until this brief is STATUS approved and founder says start extract.
- Prefer Foundation metadata (sample, method) over a flattened amount.
- Canonical units stay those in canonical-nutrients.json; convert, do not redefine.
- One USDA nutrient number may map to at most one canonical id in this pilot. Conflicts (e.g. three Energy rows) must be listed, not silently picked.
- Do not invent Nutrient ids beyond the canonical file unless marked PROPOSED and left unmapped.

UNKNOWN:
- Exact Foundation release we will pin (page listed April 2026 last time we looked; confirm on extract).
- Whether local `food_nutrient.csv` is already Foundation, mixed FDC, or something else — inspect only if founder later expands the brief.
- Which Energy measure (208 vs 957 vs 958) we treat as canonical `energy`.
